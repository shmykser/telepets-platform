## План внедрения системы характеристик питомцев

### 1. Цели и ограничения
- Сделать параметры питомцев расширяемыми без переписывания бизнес-логики.
- Привязать снижение/рост здоровья к состоянию характеристик, а не к таймеру.
- Учитывать требования: конфигурация через `config/settings.py`, SOLID/DRY, документирование в Swagger, поддержка мини-игр и экономики.

### 2. Текущее состояние (diag)
- Фоновая задача `decrease_health_task` всегда вычитает фиксированное значение из `HEALTH_DOWN_AMOUNTS`.
- В `config/settings.py` нет описания характеристик, только здоровьесвязанные словари.
- Модель `Pet` не хранит температуру/чистоту и т.п.; мини-игры фронта работают в изоляции.
- Уведомления и WebSocket события не объясняют причину падения здоровья.

### 3. Целевая концепция
1. **Характеристики по стадиям**
   - Яйцо: `temperature`, `shell_defense`.
   - Детёныш: `hunger`, `cleanliness`.
   - Взрослый: `mood`, `energy` (резерв: `socialization`).
2. **Конфигурация** (`config/settings.py`)
   - `PET_CHARACTERISTICS`: диапазоны, нормальные пороги, действия/мини-игры.
   - `HEALTH_DEGRADATION_RULES`: интервал X, коэффициенты штрафов, скорость регена.
   - `CHARACTERISTIC_ACTIONS`: как мини-игры/предметы влияют на значения.
3. **Хранение**
   - Таблица `pet_characteristics` (pet_id, key, value, status, updated_at).
   - Таблица `pet_characteristic_events` для истории (опционально, но планируется).
4. **Сервисы**
   - `PetCharacteristicService`: CRUD характеристик, расчёт штрафов, инициализация при смене стадии.
   - `HealthService`: агрегирует итоговое снижение/восстановление, общая точка логики здоровья.
   - `MiniGameResultService`: принимает результаты игр, повышает связанные характеристики, уведомляет фронт.
5. **Фоновая задача**
   - Ждёт интервал `interval_seconds` для стадии, затем
     ```
     drop_amount = base_drop + Σ penalty(char)
     if drop_amount > 0 -> уменьшение здоровья
     else -> regen_amount (до HEALTH_MAX)
     ```
   - Обновляет `updated_at` характеристик и отправляет события (`characteristics_changed`, `health_changed`).

### 4. Пошаговая реализация
1. **Конфиги и типы**
   - Добавить словари характеристик и правил в `config/settings.py`.
   - Создать Pydantic-схемы/TypedDict в `api/schemas/common.py` для сериализации.
2. **Модели + миграции**
   - Alembic: `pet_characteristics`, `pet_characteristic_events`.
   - SQLAlchemy-модели в `models/pets.py` или новом модуле.
3. **Сервисы**
   - Новый модуль `services/pet_characteristics.py`.
   - Новый модуль `services/health_engine.py` (или аналогичный) c API:
     - `calculate_next_state(pet, characteristic_snapshot)`
     - `apply_degradation(db, pet, delta)`
4. **Фоновая логика**
   - Переписать `core/tasks.decrease_health_task` на использование `HealthService`.
   - Добавить агрегированные метрики в `core/monitoring`.
5. **API и схемы**
   - Расширить `/summary` и `/summary/all` (через `PetSummaryService`) характеристиками.
   - Добавить эндпоинт `/api/pets/{pet_id}/characteristics` (GET/PATCH).
   - Добавить `/api/games/{pet_id}/result` или расширить текущий `/games` роутер.
6. **WebSocket/кеш**
   - Дополнить `CacheService` кешированием характеристик.
   - Отправлять событие `characteristics_changed`.
7. **Frontend**
   - Расширить типы, добавить отображение характеристик в `PetCarousel`, `QuickStats`.
   - Обновить мини-игры: отправка результатов в новый API, оптимистичное обновление.
   - Показ таймеров X и расшифровки штрафов.
8. **Уведомления и экономика**
   - `telegram_client`: новые сообщения о критичных характеристиках.
   - `EconomyService`: предметы/действия влияют на характеристики.
9. **Тесты, документы, миграции**
   - Unit + интеграционные тесты на сервисы и фоновые задачи.
   - README/Swagger обновить, краткая инструкция в `docs/`.

### 5. Ближайшие дев-серии
1. **Серия A (backend-основа)**
   - Конфиги, миграции, сервисы, рефактор `decrease_health_task`.
2. **Серия B (API/WS + интеграция мини-игр)**
   - Эндпоинты характеристик, события, адаптация `games` API.
3. **Серия C (frontend + UX)**
   - UI характеристик, обновление мини-игр, уведомления.
4. **Серия D (анализ и баланс)**
   - Метрики, алерты, настройка коэффициентов, документирование Notion.

### 6. Риски и меры
- **Сложность миграции**: обеспечить дефолтные значения при создании записей, откаты безопасны.
- **Синхронизация фронт/бэк**: сначала катим API + WS, затем фронт (feature flag).
- **Балансировка**: добавить конфиги в `.env`/settings для оперативной настройки.
- **Производительность**: использовать пакетные запросы при обновлении характеристик, кешировать дефиниции.

Документ обновляется по мере реализации каждой серии.
