# Исправление множественных WebSocket подключений

**Дата:** 2025-10-31  
**Проблема:** Создавалось множество WebSocket подключений (100+ попыток подключения)

---

## ❌ Проблема

### Симптомы:
- В Network tab видно **100+ попыток подключения** к `ws://localhost:8080/api/ws/pets/273065571`
- Каждый компонент, который вызывал `usePetWebSocket()`, создавал **новое подключение**
- Множественные подключения создавали избыточную нагрузку на сервер и клиент

### Причина:
`usePetWebSocket` вызывался из нескольких мест:
1. `usePet()` hook
2. `useAllPets()` hook  
3. `useWallet()` hook
4. `useAuctions()` hook
5. `PetCard.tsx` component

**Каждый вызов создавал новое WebSocket соединение!** Это неправильно - должно быть только одно подключение на все приложение.

---

## ✅ Решение

### Реализован Singleton паттерн

**Файл:** `telepets-platform/frontends/webapp/src/hooks/usePetWebSocket.ts`

**Изменения:**

1. **Глобальный singleton WebSocket:**
   ```typescript
   let globalWebSocket: WebSocket | null = null
   let globalReconnectTimeout: number | null = null
   let globalReconnectAttempts = 0
   let globalHeartbeatInterval: number | null = null
   let globalIsConnected = false
   let globalUserId: string | null = null
   ```

2. **Система подписчиков:**
   - `subscribers` - компоненты, подписанные на изменения состояния подключения
   - `queryClientSubscribers` - queryClient для обработки сообщений

3. **Проверка перед созданием нового подключения:**
   ```typescript
   // Если уже подключены для этого пользователя, не создаем новое подключение
   if (globalWebSocket && globalWebSocket.readyState === WebSocket.OPEN && globalUserId === userId) {
     console.log('[WebSocket] Уже подключено для пользователя', userId)
     return
   }
   ```

4. **Централизованная обработка сообщений:**
   - Все сообщения обрабатываются в `handleWebSocketMessage()`
   - Все зарегистрированные `queryClient` получают обновления

5. **Умная очистка:**
   - WebSocket закрывается только когда все подписчики отписались
   - Если остались другие подписчики, соединение остается активным

## 🔄 Как это работает

1. **Первый компонент вызывает `usePetWebSocket()`:**
   - Проверяет, есть ли уже активное подключение
   - Если нет - создает новое WebSocket соединение
   - Регистрирует себя как подписчика

2. **Последующие компоненты вызывают `usePetWebSocket()`:**
   - Проверяют, есть ли уже активное подключение
   - Если да - просто регистрируются как подписчики
   - **НЕ создают новое подключение**

3. **При получении сообщения:**
   - `handleWebSocketMessage()` обрабатывает сообщение
   - Все зарегистрированные `queryClient` получают обновления

4. **При размонтировании компонента:**
   - Компонент отписывается от подписчиков
   - Если это был последний подписчик - WebSocket закрывается
   - Если остались другие подписчики - соединение остается активным
