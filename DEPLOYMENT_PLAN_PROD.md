# План деплоя на Production

## 📋 Сводка изменений

### Основные изменения в dev:
1. **Миграции БД:**
   - Добавлены поля `image_egg_url`, `image_baby_url`, `image_adult_url` в таблицу `pets`
   - Удалены поля `image_egg_b64`, `image_baby_b64`, `image_adult_b64` из таблицы `pets`
   - Миграции: `2025_10_30_000005_add_pet_image_urls.py`, `2025_10_30_000006_drop_pet_image_b64.py`

2. **Хранение изображений:**
   - Перенос с base64 в БД на Cloudflare R2 (S3-compatible)
   - Новый сервис `services/r2_storage.py` для работы с R2
   - Обновлен API `api/pet_images.py` для работы с R2

3. **Генерация изображений:**
   - Переход с HuggingFace на Replicate
   - Новый провайдер `services/generation/replicate_client.py`
   - Фабрика провайдеров `services/generation/factory.py`
   - Переменная окружения `GENERATION_PROVIDER` (replicate|hf)

4. **Новая игра:**
   - Добавлена игра EggDefense для питомцев в состоянии "egg"
   - Компонент `EggDefenderGame.tsx` для фронтенда
   - Интеграция в `PetCard.tsx`

5. **Зависимости:**
   - Добавлен `boto3>=1.34.0` для работы с Cloudflare R2
   - Уже есть `replicate>=0.25.0`

#### В Render (для backend сервиса):
Необходимые переменные окружения:

**Cloudflare R2:**
- `R2_ACCOUNT_ID` - Account ID Cloudflare
- `R2_ACCESS_KEY_ID` - Access Key ID для R2
- `R2_SECRET_ACCESS_KEY` - Secret Access Key для R2
- `R2_ENDPOINT` - Endpoint URL (например: `https://<account>.r2.cloudflarestorage.com`)
- `R2_BUCKET` - Имя бакета
- `R2_PUBLIC_BASE_URL` - Публичный URL для доступа (опционально, если используется CDN)
- `R2_USE_SIGNED_URLS` - `true` или `false` (использовать подписанные URL)
- `R2_SIGNED_URL_TTL` - TTL для подписанных URL в секундах (по умолчанию 3600)

**Replicate:**
- `GENERATION_PROVIDER` - `replicate` (по умолчанию replicate)
- `REPLICATE_API_TOKEN` - API токен Replicate
- `REPLICATE_MODEL` - Модель (по умолчанию `black-forest-labs/flux-1.1-pro`)
- `REPLICATE_TIMEOUT` - Таймаут в секундах (по умолчанию 180)
- `REPLICATE_POLL_INTERVAL` - Интервал опроса статуса (по умолчанию 2)

**Существующие переменные (не изменяем):**
- `DATABASE_URL` - уже настроен
- `TELEGRAM_BOT_TOKEN` - уже настроен
- `SECRET_KEY` - уже настроен
- `ENVIRONMENT` - установить в `production` (если не установлено)
- `RUN_MIGRATIONS_ON_STARTUP` - `true` (для автоматического применения миграций)

## ⚠️ Важные замечания

1. **Миграции БД:**
   - Сначала применить миграцию добавления полей (000005)
   - Затем применить миграцию удаления полей (000006)
   - Убедиться, что данные не потеряются (URL должны быть заполнены перед удалением base64)

2. **Изображения:**
   - Старые изображения в base64 останутся в БД, но не будут использоваться
   - Новые изображения будут генерироваться и сохраняться в R2
   - При первом запросе изображения оно будет сгенерировано и загружено в R2

3. **Генерация изображений:**
   - Если Replicate недоступен, можно переключиться на HuggingFace через `GENERATION_PROVIDER=hf`
   - Но рекомендуется использовать Replicate для production

4. **Backward compatibility:**
   - Старый код с base64 не сломается, но будет игнорироваться
   - API будет возвращать URL на R2 вместо base64
