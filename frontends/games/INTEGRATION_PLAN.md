# План интеграции нового пакета `games` с WebApp

> Цель: подготовить современную инфраструктуру для мини-игр Telepets, повторно используя лучшие практики текущего WebApp и постепенно мигрируя код из `games_old`.

## 1. Архитектурные принципы

- **Единая тема и токены** — цвета, шрифты, тени, радиусы подтягиваем из `frontends/webapp` через общий конфиг (при необходимости вынести в shared-пакет).
- **React как “рамка”** — каждую игру встраиваем в React-компонент, что упрощает управление жизненным циклом, состоянием и интеграцией с Telegram WebApp.
- **Phaser как движок геймплея** — отвечаем на взаимодействие, рендер и физику. Минимум UI внутри Phaser, максимум — в React HUD.
- **Чистые модули** — игровые системы (генераторы, контроллеры, эффекты и т.д.) переносим по частям из `games_old`, отделяя данные/логику от рендеринга.
- **Коммуникация** — `postMessage`/`@twa-dev/sdk` для обмена событиями (ready, progress, end). Интерфейс описываем типами.
- **Тестируемость** — ядро (алгоритмы, генераторы) выносим в чистые функции с unit-тестами; UI/интеграцию проверяем Playwright.

## 2. Технические этапы

### Этап А. Базис (уже выполнено)
1. Создан новый проект `frontends/games` (React 19 + Vite 7 + Phaser 3.90).
2. Настроена базовая сцена `PlaceholderScene` и React-обёртка `PhaserCanvas`.
3. Обновлена инфраструктура: ESLint, TypeScript, алиасы модулей, `.gitignore`, скрипты.
4. Старый код сохранён в `frontends/games_old`.

### Этап B. Подготовка интеграции
1. **Общий дизайн-токен**: выделить набор переменных (цвета, градиенты, типографика) и синхронизировать с WebApp (`settings.ts`).
2. **Маршрутизация**: поддерживать навигацию `/games/:scene/*` через `react-router-dom`, хранить метаданные сцен в общем реестре.
3. **HUD-компоненты**: создать React-слой для overlay (панели статуса, таймеры, кнопки), подключить стек анимаций (Framer Motion либо CSS).
4. **Коммуникация**: сформировать контракт событий (`GameEventPayloads`), обработчики в WebApp и SDK-адаптер для Telegram.
5. **Состояние**: добавить лёгкий стор (Zustand) для хранения данных игры и синхронизации с бэкендом/React Query.
6. **Лоадер ассетов**: реализовать сервис загрузки с учётом CDN/кэша (поддержка dev/prod).

### Этап C. Миграция систем
1. Перенести базовые утилиты и типы (worldTypes, PetControl) в `src/modules`.
2. Адаптировать генераторы и менеджеры состояний, обновив API под новую структуру.
3. Реализовать новую прогулочную сцену, используя обновлённые системы и общий HUD.
4. Интегрировать завершение с API (economy rewards, save-progress).
5. Добавить автоматические тесты (Playwright сценарии + unit для генераторов).

## 3. Контрольная проверка

- `npm run lint` и `npm run build` в `frontends/games`.
- e2e-сценарии Playwright (Smoke: запуск сцены, reset, postMessage).
- Проверка `frontends/webapp`: встраивание нового iframe/компонента, корректный обмен событиями.
- Обновление документов: `ENDPOINTS_GUIDE.md`, Notion-страницы (по шаблону пользователя).

## 4. Ответственность и риски

- **Риски**: рассинхронизация токенов, дублирование логики при переносе, устаревшие ассеты.
- **Снижение**: ревью каждого PR на соответствие принципам DRY/SOLID, постепенная миграция, удаление устаревших модулей после покрытия тестами.

Документ будет расширяться по мере миграции модулей и согласования UX/художественных решений.
